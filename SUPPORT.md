# Support

This document explains where to ask questions, where to report defects, and how to route security or commercial requests.

## 1. Use the right channel

### GitHub Discussions

Use Discussions, when enabled, for:

- usage questions
- installation help
- environment guidance
- roadmap ideas
- architecture discussion

### GitHub Issues

Use Issues for:

- reproducible defects
- runtime failures
- frontend or backend regressions
- documentation inaccuracies

### Security reports

Do **not** open public issues for vulnerabilities.

Follow [`SECURITY.md`](./SECURITY.md).

### Commercial requests

Commercial usage, delivery, managed service, consulting, or revenue-generating use requires separate written permission.

Use:

- [`COMMERCIAL-LICENSE.md`](./COMMERCIAL-LICENSE.md)
- [`LICENSE`](./LICENSE)
- [`docs/licensing.md`](./docs/licensing.md)
- [`docs/legal-notice.md`](./docs/legal-notice.md)

## 2. Before opening an issue

Review the relevant docs first:

- [`README.md`](./README.md)
- [`CONTRIBUTING.md`](./CONTRIBUTING.md)
- [`SECURITY.md`](./SECURITY.md) when security may be involved

## 3. Include this information

Provide:

- operating system
- installation method or source workflow used
- exact commands used
- expected result
- actual result
- logs, stack traces, screenshots, or browser console output when relevant
- whether the issue is reproducible

## 4. Support boundary

Support is best-effort unless a separate written commercial agreement states otherwise.

When reporting issues, be explicit about:

- whether the problem is from a specific product or this central repository
- whether the issue occurs on Linux, Windows, or macOS
- whether the report is about runtime behavior, documentation wording, or legal/licensing interpretation

## 5. Legal note

For legal and licensing terms, use the files listed in the licensing section of [`README.md`](./README.md).

Questions about trademark attribution, no-endorsement wording, commercial boundary interpretation, or external publication should be routed through the legal and licensing documents before any public or customer-facing use.

# Hỗ trợ

Tài liệu này giải thích nơi đặt câu hỏi, nơi báo cáo lỗi và cách định tuyến yêu cầu bảo mật hoặc thương mại.

## 1. Sử dụng kênh đúng

### GitHub Discussions

Sử dụng Discussions, khi được bật, cho:

- câu hỏi sử dụng
- trợ giúp cài đặt
- hướng dẫn môi trường
- ý tưởng lộ trình
- thảo luận kiến trúc

### GitHub Issues

Sử dụng Issues cho:

- lỗi có thể tái tạo
- lỗi cài đặt hoặc thời gian chạy
- hồi quy frontend hoặc backend
- tài liệu không chính xác

### Báo cáo bảo mật

**Không** mở issue công khai cho lỗ hổng bảo mật.

Tham khảo [`SECURITY.md`](./SECURITY.md).

### Yêu cầu thương mại

Sử dụng thương mại, giao hàng, dịch vụ quản lý, tư vấn hoặc sử dụng tạo doanh thu yêu cầu sự cho phép bằng văn bản riêng.

Sử dụng:

- [`COMMERCIAL-LICENSE.md`](./COMMERCIAL-LICENSE.md)
- [`LICENSE`](./LICENSE)
- [`docs/licensing.md`](./docs/licensing.md)
- [`docs/legal-notice.md`](./docs/legal-notice.md)

## 2. Trước khi mở issue

Xem xét tài liệu liên quan trước:

- [`README.md`](./README.md)
- [`CONTRIBUTING.md`](./CONTRIBUTING.md)
- [`SECURITY.md`](./SECURITY.md) khi có liên quan đến bảo mật

## 3. Bao gồm thông tin này

Cung cấp:

- hệ điều hành
- phương pháp cài đặt hoặc quy trình làm việc nguồn đã sử dụng
- lệnh chính xác đã sử dụng
- kết quả dự kiến
- kết quả thực tế
- nhật ký, dấu vết ngăn xếp, ảnh chụp màn hình hoặc đầu ra bảng điều khiển trình duyệt khi liên quan
- vấn đề có thể tái tạo được không

## 4. Ranh giới hỗ trợ

Hỗ trợ là nỗ lực tốt nhất trừ khi có thỏa thuận thương mại bằng văn bản riêng quy định khác.

Khi báo cáo sự cố, hãy rõ ràng về:

- vấn đề đến từ sản phẩm cụ thể hay kho mã nguồn trung tâm này
- sự cố xảy ra trên Linux, Windows hay macOS
- báo cáo về hành vi thời gian chạy, nội dung tài liệu hay diễn giải pháp lý/cấp phép

## 5. Ghi chú pháp lý

Đối với điều khoản pháp lý và cấp phép, sử dụng các tệp được liệt kê trong phần cấp phép của [`README.md`](./README.md).

Câu hỏi về ghi nhận nhãn hiệu, nội dung không chứng nhận, diễn giải ranh giới thương mại hoặc công bố ra bên ngoài nên được định tuyến thông qua tài liệu pháp lý và cấp phép trước khi sử dụng công khai hoặc面向 khách hàng.
